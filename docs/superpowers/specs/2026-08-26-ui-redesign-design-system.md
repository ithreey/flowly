# Flowly 界面重构设计系统

**日期**: 2026-08-26  
**状态**: 已确认  
**预览文件**: `app/ui-redesign-preview.html`  
**目标**: 将现有较粗糙的 Element Plus 默认界面重构为现代化、轻科技感、操作简洁的桌面抓包/代理调试工作台。

---

## 1. 设计定位

Flowly 是开发者和调试人员使用的 MITM 代理、流量监控、规则配置工具。界面不应走官网、营销页或装饰型大屏路线，而应体现专业工具的高效率、高信息密度和明确运行状态。

最终方向固定为：

- **深色专业工作台**
- **Network 面板式流量表格**
- **轻科技感背景和状态反馈**
- **克制的卡片、边框、发光效果**
- **少装饰、少解释、多可操作控件**

核心设计关键词：

- 专业
- 克制
- 精密
- 清晰
- 可扫读
- 开发者工具感

---

## 2. 视觉原则

### 2.1 保持工具属性

界面第一目标是帮助用户快速完成以下动作：

- 判断代理是否运行
- 查看当前监听地址和系统代理状态
- 筛选、定位、阅读流量记录
- 查看请求/响应详情
- 管理规则
- 导出 HAR 或清空记录

不使用大面积营销式标题、插画、夸张渐变、过度动效或装饰图形。

### 2.2 科技感来源

科技感来自以下元素，而不是花哨动画：

- 深色背景
- 精细网格纹理
- 青蓝描边
- 运行状态绿色光点
- 等宽字体用于 URL、Header、Body、JSON、耗时、大小
- 半透明面板和轻微 blur
- 状态码、方法、规则启用状态的结构化色彩

### 2.3 信息密度

这是桌面端工具，信息密度应高于普通后台管理系统。

- 表格行高保持紧凑，但不拥挤。
- 顶部工具栏只放常用操作。
- 详情区域优先展示请求关键信息。
- 设置页按任务分组，不堆叠无结构表单。

| 用途          | 颜色                        |
| ------------- | --------------------------- |
| 页面背景      | `#08111F`                   |

| 主面板        | `#0F1B2D`                   |
| 次级面板      | `#121F33`                   |
| 悬浮/强调面板 | `#17263C`                   |
| 主文字        | `#E5EDF8`                   |
| 次级文字      | `#8FA1B7`                   |
| 弱文字        | `#65748A`                   |
| 普通边框      | `rgba(148, 163, 184, 0.18)` |
| 强调边框      | `rgba(56, 189, 248, 0.34)`  |

### 3.2 功能色

| 用途             | 颜色      |
| ---------------- | --------- |
| 运行/成功        | `#22C55E` |
| 主强调/链接/聚焦 | `#38BDF8` |
| 信息蓝           | `#3B82F6` |

| 错误/危险        | `#F87171` |

### 3.3 使用规则

- 页面整体以深蓝黑为主，不做纯黑。
- 青蓝只用于选中、聚焦、边框强调、链接、复制按钮。
- 绿色只用于运行状态、成功、启动类主操作。
- 红色只用于停止、删除、错误状态。
- 不使用紫色/蓝紫渐变作为主视觉，避免泛 AI 风格。

## 5. 全局布局

### 5.1 桌面主结构

固定为两层工作台布局：

```text
┌──────────────┬────────────────────────────────────┐
│ 左侧导航      │ 顶部状态栏                          │
│              ├────────────────────────────────────┤
│              │ 主内容区                            │
│              │ ┌────────────────────┬───────────┐ │
│              │ │ 列表/设置/规则区域   │ 详情面板   │ │
│              │ └────────────────────┴───────────┘ │
└──────────────┴────────────────────────────────────┘
```

### 5.2 左侧导航

宽度：

- 标准桌面：`236px`
- 窄屏：收缩为 `78px`，隐藏文字，仅保留图标

内容：

- 品牌区：`Flowly` + `Proxy Inspection Console`
- 主导航：
  - 流量监控
  - 规则配置
  - 证书管理
  - 代理设置
  - 应用设置
- 底部运行信息：
  - 监听地址
  - 运行状态点

导航选中态：

- 青蓝描边
- 轻微青蓝背景
- 左侧 3px 青蓝指示条

### 5.3 顶部状态栏

顶部状态栏固定展示当前页面上下文和全局代理状态。

左侧：

- 页面标题
- 一句话说明

右侧：

- 代理运行状态
- 系统代理状态
- 启动/停止主按钮

主按钮规则：

- 运行中显示“停止代理”，使用绿色或危险色时需和状态语义保持一致。
- 停止时显示“启动代理”，使用绿色主按钮。
- 操作中显示 loading，不允许界面无反馈。

## 6. 组件规范

### 6.1 面板

面板用于工具区域、详情区域、设置分组。

```css
border: 1px solid rgba(148, 163, 184, 0.18);
border-radius: 10px;
background: rgba(15, 27, 45, 0.78);
box-shadow: 0 24px 70px rgba(0, 0, 0, 0.34);
```

规则：

- 页面级区域可以使用面板。
- 不要出现卡片套卡片的复杂层级。
- 单个重复项允许使用小卡片，如规则摘要卡。
- 圆角控制在 `8px-10px`，不要做大圆角。

### 6.2 按钮

按钮高度：

- 默认：`34px`
- 紧凑区域：`30px`

按钮样式：

- 普通按钮：深色底、浅边框、hover 青蓝边框
- 主按钮：绿色渐变或绿色实底
- 危险按钮：红色文字/边框，删除和停止类操作使用

规则：

- hover 只改变颜色、边框、背景。
- 不使用 scale 造成布局跳动。
- 所有可点击元素必须有 `cursor: pointer`。
- focus 状态必须可见。

### 6.3 标签

标签用于方法、状态码、筛选、选中数量、运行状态。

请求方法：

| 方法      | 颜色策略 |
| --------- | -------- |
| GET       | 青蓝     |
| POST      | 紫色     |
| PATCH/PUT | 琥珀     |
| DELETE    | 红色     |

状态码：

| 状态    | 颜色策略 |
| ------- | -------- |
| 2xx/3xx | 绿色     |
| 4xx     | 琥珀     |
| 5xx     | 红色     |
| 未知    | 灰色     |

### 6.4 输入框

搜索和筛选输入：

- 高度 `34px`
- 深色背景
- 细边框
- focus 青蓝描边和轻微外发光

占位文字必须简洁，例如：

- `URL 过滤`
- `请求方法`
- `搜索规则`

## 7. 流量监控页规范

流量监控页是主体验页面，必须优先重构。

### 7.1 页面结构

```text
顶部状态栏
主内容区
  ├─ 工具栏
  ├─ 流量表格
  └─ 规则快捷概览/辅助状态区
右侧详情面板
```

### 7.2 工具栏

从左到右：

1. URL 搜索
2. 请求方法筛选
3. 状态/高级筛选入口
4. 已选数量
5. 导出 HAR
6. 清空

工具栏原则：

- 保持单行优先。
- 常用控件直接展示。
- 低频筛选可以进入弹出层，不堆满工具栏。

### 7.3 表格

列建议：

| 列   | 说明                  |
| ---- | --------------------- |
| 选择 | 批量导出/删除         |
| 方法 | 彩色方法标签          |
| 状态 | 彩色状态码            |
| URL  | 主域名 + 次级路径     |
| 大小 | 请求/响应大小或总大小 |
| 耗时 | 右对齐                |
| 时间 | 捕获时间              |

表格规则：

- 表头使用弱文字和大写英文字段风格，增强工具感。
- 行 hover 使用轻微青蓝背景。
- 选中行使用更明显但不刺眼的青蓝背景。
- URL 用等宽字体，域名和路径拆开显示。
- 数字列右对齐。

### 7.4 空状态

空状态不使用长句堆叠。

建议文案：

```text
暂无流量
启动代理并配置系统代理后，新的 HTTP/HTTPS 会话会显示在这里。
```

可附两个操作：

- 启动代理
- 打开代理设置

## 8. 详情面板规范

详情面板用于替代粗糙的普通抽屉阅读体验。桌面宽屏下优先作为右侧固定详情区；空间不足时保留抽屉模式。

### 8.1 顶部信息

展示：

- 请求方法
- 状态码
- 完整 URL
- 耗时
- 请求大小
- 响应大小

### 8.2 内容分区

Tab 固定为：

- 请求
- 响应
- 时间线

请求 Tab：

- 请求行
- Headers
- Body
- Body 格式切换：原文 / JSON / Form

响应 Tab：

- 状态行
- Headers
- Body
- Body 格式切换：原文 / JSON

时间线 Tab：

- 后续可扩展 DNS、连接、发送、等待、接收阶段。
- 当前没有完整数据时可显示基础耗时摘要。

### 8.3 代码块

代码区域固定深色：

```css
background: #07101d;
color: #cde6ff;
border: 1px solid rgba(56, 189, 248, 0.18);
border-radius: 8px;
font-family: "Cascadia Mono", "JetBrains Mono", Consolas, monospace;
font-size: 12px;
line-height: 1.55;
```

规则：

- 复制按钮放在代码块标题行右侧。
- JSON 格式化失败时给出简短说明。
- 不要让长 URL 或长 Header 撑破布局，必须换行或横向滚动。

## 9. 规则配置页规范

规则配置页应从“表格 + JSON 按钮”升级为规则管理工作台。

### 9.1 列表展示

每条规则至少展示：

- 启用开关
- 规则名称
- 匹配摘要
- 动作摘要
- 编辑
- JSON 高级编辑
- 删除

优先让用户不用打开 JSON 就能理解规则做什么。

### 9.2 操作区

顶部右侧：

- 新增规则
- 导入 JSON

删除操作：

- 弱化展示
- 必要时加确认
- 不与主操作放在同等视觉权重

### 9.3 JSON 模式

JSON 编辑保留为高级模式：

- 使用暗色 CodeMirror 主题
- 保存前校验 JSON
- 错误提示定位到 JSON 模式内部

## 10. 设置类页面规范

适用于：

- 证书管理
- 代理设置
- 应用设置

### 10.1 分组方式

设置项使用任务分组：

- 当前状态
- 监听配置
- 系统代理
- 证书安装
- 高级选项
- 危险操作

### 10.2 状态卡

关键状态使用小型状态卡：

- 证书是否已安装
- 系统代理是否启用
- 监听地址是否有效
- 上游代理是否配置

### 10.3 危险区域

危险操作放到底部独立区域：

- 清除配置
- 卸载证书
- 停止代理

使用红色边框或红色文字，但不大面积铺红。

## 11. 动效与反馈

### 11.1 动效时长

| 场景          | 时长                             |
| ------------- | -------------------------------- |
| hover         | `150ms-180ms`                    |
| focus         | `150ms`                          |
| 抽屉/面板进入 | `200ms-250ms`                    |
| loading       | 按 Element Plus 默认或轻量自定义 |

### 11.2 禁止项

- 禁止持续装饰动画。
- 禁止图标弹跳。
- 禁止大面积闪烁发光。
- 禁止 hover scale 导致布局变化。

### 11.3 必须项

- 异步操作必须有 loading 或 disabled 状态。
- 复制、导出、保存、删除必须有成功/失败反馈。
- 启动/停止代理必须有明确运行态变化。

---

## 12. 响应式规则

虽然这是桌面工具，但仍需适配窄窗口。

### 12.1 宽屏

`>= 1180px`：

- 左侧完整导航
- 顶部状态栏
- 主表格 + 右侧详情面板并排

### 12.2 窄屏

`< 1180px`：

- 左侧导航收缩为图标栏
- 隐藏导航文字和底部运行卡
- 主内容区单列
- 详情面板改为抽屉或隐藏，点击行后打开

### 12.3 最小可用宽度

目标最低支持宽度：`900px`。

如窗口更窄：

- 工具栏允许换行。
- 表格允许横向滚动。
- 不允许正文和按钮文字互相重叠。

## 13. Element Plus 适配策略

现有项目基于 Vue 3 + Element Plus，不引入新的组件库。

### 13.1 保留

- `el-table`
- `el-button`
- `el-input`
- `el-select`
- `el-tag`
- `el-drawer`
- `el-dialog`
- `el-tabs`
- `el-switch`
- `el-message`

### 13.2 重写

通过全局 CSS 和 scoped 样式重写：

- 背景
- 边框
- 表格行 hover
- 表头
- 输入框 focus
- 按钮 hover
- Drawer 背景
- Dialog 背景
- Tabs 样式

### 13.3 图标

继续使用 `@element-plus/icons-vue`。

规则：

- 不使用 emoji 作为 UI 图标。
- 图标尺寸统一。
- 图标按钮必须有可理解的文本或 tooltip。

## 15. 验收标准

视觉验收：

- 页面不再呈现 Element Plus 默认白底后台风格。
- 轻科技感明显，但不花哨。
- 主操作一眼可见。
- 流量表格可快速扫读。
- 详情代码区域更适合阅读请求/响应数据。

交互验收：

- 所有按钮和可点击项有 hover 状态。
- 所有异步操作有 loading 或 disabled 状态。
- 键盘 focus 可见。
- 窄屏无内容重叠。
- 表格长 URL 不撑破布局。

技术验收：

- 不引入新的 UI 组件库。
- 不破坏现有业务逻辑。
- `npm run build` 通过。
- 主要页面在 `1366x768` 和 `1440x900` 下可用。
